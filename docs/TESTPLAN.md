# COBOL Account Management Test Plan

This plan captures the current COBOL behavior for stakeholder review and as a basis for Node.js unit and integration tests. Run behavioral cases in a fresh application process unless a case explicitly tests multiple operations in one process. Record observed output in **Actual Result** and change **Status** from `Not Run` to `Pass` or `Fail` after execution. Cases marked for stakeholder decision describe behavior that the current implementation does not define or support.

| TC-012 | Student/account separation is not implemented | Start the application. | 1. Inspect the menu and available inputs for a student or account identifier; 2. | TC-013 | Invalid, negative, and out-of-range transaction input | Start a fresh process for each input variation. | 1. | TC-014 | Balance capacity and credit overflow | Start a fresh process; balance is `1000.00`. | 1. Credit `999000`, which is within the amount field's six-integer-digit capacity; 2. Do not use overflow or truncation behavior as the Node.js business requirement without stakeholder approval. |
